# Sneaker Vault GH

Production-oriented headless storefront for a Ghana-based sneaker reseller.
The app uses Next.js, TypeScript, Tailwind CSS, Shopify Headless, Shopify
Customer Accounts, and Shopify checkout with Paystack.

## Commerce architecture

- Shopify Admin is the source of truth for products, EU size variants, prices,
  inventory, customers, carts, and orders.
- Product and cart requests use the server-only Storefront API token. The token
  is never sent to browser JavaScript.
- Shopify hosts passwordless customer sign-in and emails the six-digit code.
  The storefront verifies the OIDC response and keeps Shopify tokens in an
  encrypted, HttpOnly session cookie.
- Checkout requires a signed-in customer. The current customer token is
  attached to the Shopify cart before the customer leaves for Shopify
  checkout.
- Paystack remains a Shopify payment provider. There are no Paystack API keys
  or SDK calls in this codebase.
- Delivery is fulfilled outside the web app by Sneaker Vault GH's delivery
  partner.

If Shopify is not configured, unreachable, or has no published products, the
store visibly falls back to the fictional preview catalog. Preview products
can be placed only in a local demo bag and can never reach real checkout.

## Run locally

```bash
npm install
copy .env.example .env.local
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

```bash
npm run lint
npx tsc --noEmit
npm run build
npm run build:sites
```

## Shopify Headless setup

In **Sales channels → Headless**, open the Sneaker Vault GH storefront:

1. Copy the permanent `your-store.myshopify.com` hostname. Do not use the
   public storefront URL, an Admin URL, a scheme, or a path.
2. Copy the **private Storefront API token** generated by the Headless channel.
   Treat the token as opaque: Shopify does not document a stable prefix
   contract, and current Headless private tokens can begin `shpat_`. Verify it
   by its **Private access token** label and a successful Storefront API
   request, not by its prefix.
3. Enable Storefront access for product listings and product inventory.
4. Publish every sellable product to the Headless sales channel.
5. Keep the Shopify API version at `2026-07`.
6. Confirm Ghana is an active Shopify Market and that contextual prices are
   returned in GHS.

Use these product conventions:

- Vendor = brand
- Option name `Size`, with values such as `EU 42` or `42.5`
- Optional option name `Color` or `Colour`
- Product type = Lifestyle, Running, Basketball, Skate, or Trail
- Tags `featured` and `new-arrival` control home-page emphasis
- Each size has its own SKU, GHS price, inventory quantity, and availability
- Add useful image alt text before publishing

## Customer Accounts setup

Create a **Confidential** Customer Account API client in the Headless channel
and grant customer profile and order read permissions.

For the current private production site, register:

```text
Callback URL
https://sneaker-vault-gh.bysslimited.chatgpt.site/account/auth/callback

Logout URL
https://sneaker-vault-gh.bysslimited.chatgpt.site/account
```

Shopify does not accept an ordinary HTTP localhost callback. Use the deployed
HTTPS site while testing the login flow.

In **Settings → Checkout → Customer contact method**, enable **Require
customers to sign in to their account before checkout**. Enabling customer
accounts alone does not enforce this checkout rule.

Generate a strong application session secret with at least 32 random bytes,
for example:

```bash
openssl rand -base64 48
```

Store it as `SESSION_SECRET`; never prefix it with `NEXT_PUBLIC_`.

## Environment variables

Copy `.env.example` to `.env.local` for local work. Production values must also
be added to the Sites runtime environment; `.env.local` is not deployed.

Required for live catalog and cart:

```text
NEXT_PUBLIC_SITE_URL
SHOPIFY_STORE_DOMAIN
SHOPIFY_STOREFRONT_PRIVATE_TOKEN
SHOPIFY_API_VERSION
```

Additionally required for customer accounts:

```text
SHOPIFY_CUSTOMER_ACCOUNT_CLIENT_ID
SHOPIFY_CUSTOMER_ACCOUNT_CLIENT_SECRET
SHOPIFY_CUSTOMER_ACCOUNT_CALLBACK_URL
SESSION_SECRET
```

`SHOPIFY_WEBHOOK_SECRET` is optional until webhook-driven cache invalidation is
added. No Paystack environment variable belongs in this project.

## Paystack launch check

The configured Paystack test account is exercised only through Shopify
checkout. Before launch:

1. Complete a signed-in test purchase in GHS.
2. Confirm the Shopify order, payment status, Headless channel attribution, and
   size-level inventory adjustment.
3. Test a failed payment and a refund.
4. Confirm settlement details with the client before switching Paystack live.

See Paystack's [Shopify setup
guide](https://support.paystack.com/en/articles/2132226).
